# CRM Analytics Telegram Bot

Telegram-бот для анализа CRM-данных из CSV-выгрузки.

Проект загружает данные о заказах в SQLite-базу и позволяет получать бизнес-метрики, отчёты, график выручки, рекомендации и ответы на вопросы обычным текстом. Для обработки естественного языка используется локальная LLM qwen2.5 через Ollama.

## Возможности

Бот поддерживает команды:

- `/start` — стартовое сообщение и список возможностей.
- `/metrics` — основные метрики за текущий месяц.
- `/top_managers` — топ-5 менеджеров за текущий месяц.
- `/status_report` — распределение заказов по статусам.
- `/chart_revenue` — график выручки по дням за последние 30 дней.
- `/recommendations` — рекомендации на основе CRM-данных.

Также бот умеет отвечать на следующие вопросы написанные обычным текстом, например:

- Какая выручка была в мае?
- Сколько заказов отменено за последние 7 дней?
- Кто лучший менеджер по марже?
- Какой источник дал больше всего заказов?
- В каком городе самый высокий средний чек?

## Назначение основных модулей

### `main.py`

Точка входа в приложение. Файл создаёт объект Telegram-бота, создаёт `Dispatcher`, подключает роутер из `app.handlers` и запускает polling.

### `app/handlers.py`

Содержит обработчики Telegram-команд:

- `/start`
- `/metrics`
- `/top_managers`
- `/status_report`
- `/chart_revenue`
- `/recommendations`

Также в этом файле находится обработчик обычных текстовых сообщений. Он принимает вопросы пользователя и передаёт их в LLM-модуль.

### `app/database.py`

Отвечает за подключение к SQLite-базе данных и создание таблицы `orders`.

База хранится в папке:

```text
data/crm.db
```

### `app/metrics.py`

Содержит SQL-запросы для расчёта основных метрик:

- количество заказов за текущий месяц;
- выручка;
- маржа;
- средний чек;
- количество успешных заказов;
- количество отменённых заказов;
- процент отмен;
- количество новых клиентов;
- топ менеджеров;
- распределение заказов по статусам.

### `app/charts.py`

Содержит логику построения графика выручки.

Команда `/chart_revenue` строит график выручки за последние 30 дней, сохраняет его в папку `data/charts/` и отправляет изображение пользователю в Telegram после чего изображение удаляется из локального хранилища.

### `app/schemas.py`

Содержит Pydantic-модели для структурированных данных.

Основные модели:

- `QueryIntent` — результат разбора пользовательского вопроса через LLM.
- `RecommendationFact` — один рассчитанный факт для рекомендации.
- `RecommendationPlan` — ответ LLM со списком выбранных `fact_id`.

### `app/llm_questions.py`

Отвечает только за обращение к локальной LLM через Ollama.

Этот модуль получает вопрос пользователя и возвращает структурированный объект `QueryIntent`.

Пример вопроса:

```text
Какая выручка была в мае?
```

Пример результата:

```json
{
  "intent": "revenue",
  "start_date": "2026-05-01",
  "end_date": "2026-06-01",
  "unsupported_reason": ""
}
```

LLM не считает показатели и не выполняет SQL-запросы, а вычленаяет намерение(intent) пользоватея и диапазон дат.

### `app/intent_executor.py`

Получает `QueryIntent` и выполняет заранее подготовленный SQL-запрос.

Например, если LLM вернула:

```text
intent = revenue
```

то Python выбирает SQL-запрос для расчёта выручки.

В этом модуле также выполняется проверка периода:

- дата начала должна существовать;
- дата конца должна существовать;
- даты должны быть в формате `YYYY-MM-DD`;
- начало периода должно быть раньше конца;
- слишком большой период отклоняется.

### `app/question_answering.py`

Связывает LLM и SQL-логику.

Общий процесс:

```text
вопрос пользователя
        ↓
Ollama определяет intent и период
        ↓
Python проверяет результат
        ↓
SQLite считает реальные данные
        ↓
бот отправляет ответ
```

### `app/recommendation_facts.py`

Собирает реальные аналитические факты из базы данных.

Примеры фактов:

- менеджер с высокой долей отмен;
- источник с низкой маржинальностью;
- заказы, которые были созданы больше 7 дней назад и всё ещё находятся в статусе `new`;
- заказы без источника;
- город с низким средним чеком.

Важно: все числа считаются SQL-запросами из базы.

### `app/llm_recommendations.py`

Передаёт рассчитанные факты в Ollama.

LLM получает не всю базу, а только агрегированные факты:

```json
{
  "id": "high_manager_cancellation",
  "category": "manager",
  "priority": 35.0,
  "evidence": {
    "manager": "Иван Петров",
    "orders_count": 20,
    "cancelled_orders": 7,
    "cancellation_rate": 35.0
  }
}
```

LLM выбирает только `fact_id`, которые считает самыми важными. Она не пишет финальный текст и не придумывает числа.

### `app/recommendations.py`

Соединяет SQL-факты и LLM-выбор.

Процесс:

```text
SQL собирает факты
        ↓
LLM выбирает самые важные fact_id
        ↓
Python проверяет, что id существуют
        ↓
Python берёт готовый текст рекомендации
        ↓
бот отправляет рекомендации
```

Если Ollama недоступна, используется fallback: рекомендации сортируются по `priority` без участия LLM.

## База данных

Используется SQLite.

Основная таблица:

```text
orders
```

Поля таблицы:

```text
id
order_id
created_at
client_id
manager
status_group
revenue
cost
source
city
```

Статусы заказов:

```text
new
in_progress
complete
cancel
```

## Принципы расчёта метрик

### Выручка

Выручка считается только по завершённым заказам:

```sql
status_group = 'complete'
```

### Маржа

Маржа рассчитывается как:

```text
revenue - cost
```

### Средний чек

Средний чек рассчитывается по завершённым заказам:

```text
сумма выручки / количество завершённых заказов
```

### Доля отмен

Доля отмен рассчитывается так:

```text
количество отменённых заказов / общее количество заказов * 100%
```

### Новые клиенты

Новый клиент определяется по первому заказу в базе. Если первый заказ клиента находится в текущем месяце, клиент считается новым.

## Установка и запуск

### 1. Создать виртуальное окружение

```bash
python -m venv venv
```

### 2. Активировать виртуальное окружение

Windows PowerShell:

```bash
venv\Scripts\activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Создать `.env`

В корне проекта нужно создать файл `.env`:

```env
BOT_TOKEN=ТОКЕН БОТА ТЕЛЕГРАМ

OLLAMA_MODEL=qwen2.5:3b
OLLAMA_URL=http://127.0.0.1:11434
```

### 5. Установить и запустить Ollama

Проверить установку:

```bash
ollama --version
```

Скачать модель:

```bash
ollama pull qwen2.5:3b
```

Запустить сервер Ollama:

```bash
ollama serve
```

Проверить, что сервер работает:

```bash
curl http://127.0.0.1:11434
```

Ожидаемый ответ:

```text
Ollama is running
```

### 6. Импортировать данные

```bash
python -m scripts.import_crm
```

### 7. Запустить Telegram-бота

```bash
python main.py
```


## Как работает обработка обычного вопроса

Пользователь пишет:

```text
Какая выручка была в мае?
```

Дальше происходит цепочка:

```text
Telegram
   ↓
handlers.py
   ↓
question_answering.py
   ↓
llm_questions.py
   ↓
Ollama возвращает QueryIntent
   ↓
intent_executor.py
   ↓
SQLite считает реальные данные
   ↓
бот отправляет ответ
```

LLM возвращает только структурированный результат:

```json
{
  "intent": "revenue",
  "start_date": "2026-05-01",
  "end_date": "2026-06-01",
  "unsupported_reason": ""
}
```

После этого Python выбирает заранее написанный SQL-запрос.

## Безопасность LLM

В проекте не выполняется SQL, сгенерированный моделью.

LLM не получает прямой доступ к базе данных и не может выполнить любой другой произвольный SQL.

Модель возвращает только один из разрешённых `intent`:

```text
revenue
cancelled_orders
best_manager_by_margin
top_source_by_orders
city_highest_average_check
unsupported
```

Pydantic проверяет, что ответ LLM соответствует ожидаемой структуре.

Если вопрос нельзя посчитать по текущей таблице, бот отвечает:

```text
В текущей базе нет данных, чтобы посчитать этот показатель.
```

## Как работают рекомендации

Команда:

```text
/recommendations
```

работает по гибридной схеме:

```text
SQL рассчитывает реальные факты
        ↓
LLM выбирает самые важные факты
        ↓
Python формирует финальный текст
```

Пример факта:

```json
{
  "id": "low_source_margin",
  "category": "source",
  "priority": 72.5,
  "evidence": {
    "source": "Instagram",
    "revenue": 120000,
    "margin": 33000,
    "margin_rate": 27.5
  }
}
```

LLM возвращает только список id:

```json
{
  "fact_ids": [
    "low_source_margin",
    "high_manager_cancellation",
    "stale_new_orders"
  ]
}
```

Финальный текст берётся из Python-кода, где уже подставлены реальные числа из базы.

## Обработка ошибок

Если Ollama недоступна, проект не падает.

Для рекомендаций используется fallback:

```text
если LLM доступна → она выбирает важные факты
если LLM недоступна → факты сортируются по priority
```

Для обычных вопросов бот возвращает сообщение:

```text
Не удалось обработать вопрос. Попробуйте сформулировать его иначе.
```

## Ограничения проекта

- Данные берутся только из SQLite-базы.
- Если в базе нет нужного поля, показатель не рассчитывается.
- ROMI не поддерживается, потому что нет рекламных расходов.
- Налоги и зарплаты не поддерживаются, потому что таких данных нет в таблице.
- LLM используется только для понимания вопроса и выбора рекомендаций.
- Все бизнес-показатели считаются SQL-запросами, а не моделью.
